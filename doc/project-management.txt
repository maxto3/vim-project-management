1. INTRODUCTION                                     *project-management-intro*

project-management opens a project in the current Vim tab and builds a layout
similar to VS Code:

    +------------+-------------------------------+------------------+
    |            |                               | file browser     |
    |  opencode  |          editor               | (netrw, top)     |
    |  (left)    |                               |------------------|
    |            |                               | outline (bottom) |
    +------------+-------------------------------+------------------+
    |                   terminal (project root)                       |
    +-----------------------------------------------------------------+

The plugin is written in Vim9 script and requires Vim 9.  It does not support
Neovim.

==============================================================================
2. REQUIREMENTS                                 *project-management-requirements*

- Vim 9.0 or newer with |+terminal|.
- |coc.nvim| for the outline and LSP.
- The built-in netrw file browser.
- The `opencode` executable for the left panel.

Install with vim-plug from the local Git repository:

    Plug 'file:///D:/source/repos/project-management'

Run `:PlugInstall`; vim-plug clones it to
`~/.vim/plugged/project-management` and loads it from there.  Use the
`file:///` URL rather than a bare `D:/...` path, because vim-plug treats a bare
local path as a plugin directory to add to 'runtimepath' instead of cloning it.

After committing changes in the source repository, run
`:PlugUpdate project-management` to refresh the installed copy.

All `.vim` source files must use UTF-8 without BOM and LF line endings.  CRLF
causes `E1173` after `enddef` in Vim9 scripts.

3. COMMANDS                                         *project-management-commands*

                                                        *:ProjectOpen*
:ProjectOpen [path]     Open the project at {path}.  Without an argument, use
                        the current working directory.  Existing project
                        terminals and layout are closed first.

                                                        *:ProjectClose*
:ProjectClose           Close the project.  Project file buffers are wiped,
                        non-project buffers are preserved, project terminals
                        are stopped, the startup working directory is restored,
                        and one empty `[No Name]` window remains.

                                                        *:ProjectClose!*
:ProjectClose!          Force a full cleanup: all buffers, windows and tabs are
                        removed.

                                                        *:ProjectReload*
:ProjectReload          Rebuild the project layout without destroying project
                        buffers.

                                                        *:ProjectStatus*
:ProjectStatus          Show the project root, PWD, window IDs and terminal
                        buffers.

                                                        *:ProjectOutline*
:ProjectOutline         Open or focus the outline window.  Use this after the
                        language server is ready if the outline started with an
                        "Outline unavailable" placeholder.

                                                        *:ProjectFocusOutline*
:ProjectFocusOutline    Toggle focus between the center editor and the outline
                        window.  The sample vimrc maps this to <Leader>O.

                                                        *:ProjectToggleOutline*
:ProjectToggleOutline   Toggle the outline in the right column.  While a
                        project is active, |F2| calls this command.

                                                        *:ProjectFocusMode*
:ProjectFocusMode       Toggle focus mode.  The first call opens a separate
                        tab with a single window showing the project editor
                        buffer; the original layout stays untouched in its
                        own tab.  Calling it again closes that tab and
                        returns to the layout, carrying the file that was
                        opened while focus mode was active.

                                                        *:ProjectFocus*
:ProjectFocus {kind}    Move the cursor to a project window.  {kind} is one of
                        `files` (the netrw browser), `opencode`, `terminal` or
                        `outline` (the latter opens the outline when needed
                        and toggles back to the editor).
                        Reports an error when the window is gone; run
                        |:ProjectReload| to rebuild the layout.

                                                        *project-management-mappings*
MAPPINGS

The plugin defines five normal-mode mappings by default:

  <Leader>wo    Open the project at the current directory (|:ProjectOpen|).
  <Leader>wc    Close the project, keeping non-project buffers
                (|:ProjectClose|).
  <Leader>we    Jump to the file browser (netrw) window
                (|:ProjectFocus| `files`).
  <Leader>wa    Jump to the opencode window (|:ProjectFocus| `opencode`).
  <Leader>wt    Jump to the bottom terminal window (|:ProjectFocus| `terminal`).
  <Leader>wl    Jump to the outline window (|:ProjectFocus| `outline`).
  <F11>         Toggle focus mode (|:ProjectFocusMode|).

The focus mappings are also defined for terminal windows, so they work
while typing in opencode or the bottom shell without leaving Terminal-Job mode
first.

Set |g:project_management_default_mappings| to 0 before the plugin loads to
disable them and define your own keys.  |F2| remains project-aware; map
|:ProjectFocusOutline| yourself if you want a focus toggle.

                                                        *project-management-events*
EVENTS

Companion plugins can react to project lifecycle changes through user events:

  *ProjectOpened*       `User ProjectOpened`
                        Fired after the layout is built and the project is
                        active.

  *ProjectClosed*       `User ProjectClosed`
                        Fired after |:ProjectClose| has reset the project
                        state.

For example, a plugin can restore the working directory that was active
before the project was opened by handling `User ProjectClosed`.

4. LAYOUT                                             *project-management-layout*

- The current tab is collapsed to one window, then the layout is built with
  explicit `aboveleft` / `belowright` splits.
- The center window is the only editing window.  The project maps netrw's
  <CR> and double-click to open files explicitly in the center editor;
  directories stay in the browser.
- The left column runs opencode with the project root as its working
  directory.
- The bottom row runs the shell with the project root as its working
  directory.
- The right column contains netrw and the coc outline.
- File names in the browser are coloured per extension; the whole file name,
  extension included, uses that colour.  The colour is derived
  from the extension itself (golden-angle hue, saturation and lightness follow
  the current Normal background), so each extension keeps a stable, distinct
  colour and the palette follows |:colorscheme|.  Dotfiles and well-known names
  such as LICENSE, Makefile and Dockerfile get colours of their own.
- While a project is active, coc's `outline.checkBufferSwitch` is disabled and
  the plugin refreshes the outline only when the center editor's buffer
  changes.  Moving focus to netrw/terminal/opencode keeps the outline on the
  current source file.
- The plugin temporarily enables 'hidden' while a project is open and restores
  the previous value on close.

5. OPTIONS                                           *project-management-options*

                                        *g:project_management_left_width*
Default: 0.28
Left column width as a ratio of `&columns`.

                                        *g:project_management_right_width*
Default: 34
Right column width in columns.

                                        *g:project_management_bottom_height*
Default: 14
Bottom terminal height in lines.

                                        *g:project_management_winminwidth*
Default: 20
Minimum width used when computing the side columns.

                                        *g:project_management_winminheight*
Default: 5
Minimum height used when computing the bottom terminal and outline.

                                        *g:project_management_opencode_cmd*
Default: `opencode`
Executable used for the left panel.

                                        *g:project_management_opencode_args*
Default: `[]`
Extra arguments passed to opencode, for example `['--continue']`.

                                        *g:project_management_shell*
Default: empty
Shell used for the bottom terminal.  Empty means `&shell`.

                                        *g:project_management_enable_terminals*
Default: 1
Set to 0 to create placeholder buffers instead of starting opencode and the
shell terminal.  Intended for headless tests.

                                        *g:project_management_enable_netrw*
Default: 1
Set to 0 to use a placeholder buffer instead of netrw.  Intended for tests.

                                        *g:project_management_netrw_ext_groups*
Default: {}
Override the generated extension colours.  A |Dictionary| that maps an
extension (without the dot) to a highlight group; that group's foreground
colour is used for matching file names.  Example: >
  let g:project_management_netrw_ext_groups = {'md': 'Title', 'py': 'Function'}
<

                                        *g:project_management_default_mappings*
Default: 1
Define the default <Leader>wo and <Leader>wc mappings.  Set to 0 before the
plugin loads to define your own keys.

                                        *g:project_management_opencode_esc*
Default: `'app'`
Esc policy for the opencode terminal: `'app'` passes Esc to opencode,
`'normal'` maps it to Terminal-Normal.

                                        *g:project_management_terminal_esc*
Default: `'normal'`
Esc policy for the project bottom shell.  `'app'` passes Esc to the shell,
`'normal'` maps it to Terminal-Normal.

The coc-powershell terminal reads `g:project_management_powershell_esc` from
`_vimrc`; its default is `'normal'`.

In terminal windows, `Ctrl-W w/h/j/k/l` still performs Vim window navigation
and `Ctrl-W .` sends a literal Ctrl-W to the job.

==============================================================================
6. NOTES                                               *project-management-notes*

- The outline uses coc's `outline.splitCommand = edit` while a project is
  active and restores the previous value on close.  This makes coc open the
  outline in the reserved right-hand window instead of a new column.
- While a project is active, `outline.checkBufferSwitch` is disabled.  The
  plugin refreshes the outline only when the center editor's buffer changes,
  so moving focus to netrw, the terminal or opencode keeps the outline showing
  the source file.
- |:ProjectFocusOutline| toggles focus between the editor and the outline.
  The sample vimrc maps it to `<Leader>O`.  From the outline, |CTRL-W_p| returns
  to the previous window.
- If the LSP is not ready when the project opens, the outline window shows a
  placeholder.  Press |F2| or run |:ProjectOutline| after the language server
  is ready.
- `:ProjectClose!` is destructive by design.
- While a project is active, |F2| toggles the project outline.  Outside a
  project it keeps the normal coc outline behavior.
